1. MAIN APPLICATION PURPOSE
================================================================================
Vocabotics is an AI ORCHESTRATION platform that generates complete software 
systems in 8 calls instead of 200+ iterative calls.

Core Innovation: Vocabotics Tags
  <Button data-vocabotics-id="btn-login-2fa">Login</Button>
  Maps to: Frontend → Handler → API → Backend → Database → Tests

2. THE WORKFLOW (6 PHASES)
================================================================================
Vision Input
  ↓
PRD Generation (Sonnet 4.5)
  → 15-20 functional requirements, user stories, success metrics
  ↓
Architecture Design (Sonnet 4.5)
  → Components, data models, API contracts, security, scalability
  ↓
Code Generation (Sonnet 4.5 for complex, Haiku for tests)
  → Frontend (React) + Backend (Express) + Tests (Jest)
  ↓
Integration Mapping (Deterministic - extracts tags)
  → Complete traceability: Frontend → API → Database → Tests
  ↓
Quality Validation
  → ISO 9001, ISO 12207 compliance
  → Requirement coverage 100%
  → Test coverage 95%+
  ↓
Deployment Ready

3. PROMPT LOCATION & STRUCTURE
================================================================================
Location: /apps/api/src/services/generators/ and /apps/api/src/services/ai.service.ts

Pattern:
  System Prompt: "You are an expert [domain]. Generate [artifact] as JSON..."
  User Prompt: "Generate [artifact] for:\n[context]\n[requirements]..."
  Output: Valid JSON with specific schema

Key Generators:
  ✓ prd-generator.service.ts (vision → PRD)
  ✓ architecture-generator.service.ts (PRD → architecture)
  ✓ schema-generator.service.ts (architecture → Prisma schema)
  ✓ code-generator.service.ts (architecture → React + Express)
  ✓ Test generation in ai.service.ts

Model Selection:
  Sonnet 4.5 → Complex tasks (PRD, Architecture, Frontend code)
  Haiku 3.5 → Simple tasks (Tests, migrations, database utilities)
  Vision → Image analysis (UI validation, screenshots)

4. DATABASE (PostgreSQL) - CONVERT TO JSON FOR PYTHON CLI
================================================================================
Core Tables to Convert:

projects
  ├─ name, vision, description
  ├─ current_phase (state machine)
  ├─ technology_stack (JSON)
  └─ settings (JSON)

artifacts
  ├─ type (prd|architecture|code|schema|tests|integration_map)
  ├─ version (1, 2, 3...)
  ├─ content (JSONB - the actual artifact)
  ├─ generated_by (sonnet-4.5|haiku|vision)
  └─ status (draft|review|approved)

integration_elements
  ├─ vocabotics_id (unique tag like "btn-login-2fa")
  ├─ element_type (button|input|form|component)
  ├─ file_path, line_number
  ├─ api_endpoint, database_operations
  └─ test_references, requirement_ids

ai_calls (for cost tracking)
  ├─ model, task_type, tokens_in, tokens_out
  ├─ cost_usd, duration_ms
  └─ cached (boolean)

5. KEY ARCHITECTURAL DECISIONS
================================================================================
State Machine: Enforce strict workflow (can't skip phases)
  States: VISION → PRD_GENERATION → PRD_REVIEW → ARCHITECTURE_DESIGN → 
          ARCHITECTURE_REVIEW → SCHEMA_GENERATION → API_SPECIFICATION →
          CODE_GENERATION → CODE_REVIEW → TEST_GENERATION → 
          INTEGRATION_TESTING → QUALITY_REVIEW → DEPLOYMENT

Tags: Every element must have vocabotics-id for traceability
  Frontend: <Component data-vocabotics-id="comp-id">
  Backend: // vocabotics-id: "api-id"
  Database: -- vocabotics-requirements: REQ-ID

JSON Output: All AI responses must be valid JSON (temperature: 0.3-0.7)
  Lower temp (0.3) = more consistent code/tests
  Higher temp (0.7) = more creative PRD/architecture

Cost Tracking: Log every AI call (model, tokens, cost, duration)
